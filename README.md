# Playlist Completion with ELECTRE IS

Recommending songs to extend a playlist while keeping its "aesthetic", using a **multi-criteria decision method (ELECTRE IS)** and graph algorithms instead of machine learning, in the spirit of Spotify's *Smart Shuffle*.

> Solo project · M1 course *Collective and Multi-Criteria Decision Making* (Université Paris Dauphine – PSL) · 2025 – 2026
> 📄 [Full report (in French)](rendu.pdf)

## Result

From a catalogue of **2,884 songs** and a playlist of **131 songs**, the method selects **13 recommendations**:

| | | |
|---|---|---|
| APA – Mora | Am I Wrong – Nico & Vinz | Villa sur la côte – Laylow |
| Con Altura – ROSALÍA | Send Me on My Way – Rusted Root | 92i Veyron – Booba |
| Girls Like You – Maroon 5 ft. Cardi B | Nique les clones, Pt. II – Nekfeu | Johnny, Johnny – Jeanne Mas |
| La Modelo – Ozuna | Weak – AJR | 60 années – Damso |
| Me Gusta – Shakira | | |

The recommended songs fall right on the peaks of the playlist profile for tempo, energy and valence. Genre is the least well matched criterion (see [Limitations](#limitations)).

## How it works

```
Spotify + ReccoBeats APIs ──► song features ──► playlist profile ──► per-criterion scores
        ──► concordance matrices (ELECTRE IS) ──► outranking graph
        ──► strongly connected components (Kosaraju) ──► kernel = recommendations
```

**1. Data collection.** Songs come from 9 public Spotify playlists (French rap, jazz, classical, electronic, latino, rock, metal, French variety, all-time hits). Spotify provides tracks and artist genres; ReccoBeats provides audio features. Songs with missing features were dropped.

**2. Seven criteria.** Tempo, valence (mood), energy, instrumentalness, genre, release year and popularity. Values in [0, 1] are rescaled to integers in [0, 100].

**3. Playlist profile.** For each continuous criterion, every playlist song contributes a Gaussian kernel centred on its value. Kernels are reflected at the bounds of the range so edge values are not penalised, summed, then min-max normalised. The profile is a smooth function giving, for any value, its closeness to the playlist. A song at tempo 105 still scores well in a playlist split between 100 and 110. Genre is handled discretely, with a hand-defined 9 × 9 genre proximity matrix.

**4. Scores.** Each candidate song (playlist songs removed: 2,877 left) gets a score in [0, 1] per criterion: the value of the playlist profile at the song's feature.

**5. ELECTRE IS outranking.**
- One concordance matrix per criterion (2,877 × 2,877), with indifference threshold *q* = 0.02 and preference threshold *p* = 0.3.
- A weighted global concordance matrix, with weights from 0.05 (valence) to 0.2 (genre).
- Song A outranks song B when their global concordance exceeds *s* = 0.9. This gives a directed graph with **2,877 nodes and 1,223,483 edges**.

**6. Finding the recommendations.**
- Songs that outrank each other by transitivity are treated as equivalent: strongly connected components are found with an iterative Kosaraju algorithm, to avoid recursion limits, and merged. This gives a DAG of **253 nodes and 7,206 edges**.
- A greedy kernel search on the DAG returns a set of songs that dominates every other song without dominating each other. This set is the recommendation.


The CSV files in `data/` are enough to reproduce the results. Re-collecting data with `recupData.py` requires Spotify API credentials.

## Limitations

- **Arbitrary parameters.** The kernel widths, thresholds, weights, the outranking threshold *s* and the genre proximity matrix were tuned by hand on this playlist. Nothing guarantees they transfer to other playlists or catalogues.
- **Genre is the weak spot.** Genre scores are very close to each other, so the criterion constrains the selection little, and adding more genres would compress them further. Learned genre embeddings would be a natural improvement.
- **Limited features.** Only 9 broad genres, no sub-genres, and only the features exposed by public APIs. Features extracted from the audio itself would be richer.
- **Quadratic cost.** Concordance matrices grow as *n²*. A few minutes for 3,000 songs, unrealistic for a catalogue of hundreds of thousands.
- **No quantitative evaluation.** Recommendations are assessed by comparing their distribution with the playlist profile, not against user feedback or a baseline such as nearest neighbours in feature space.
